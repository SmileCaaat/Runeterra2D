# 英雄参考与改编原则

## 核心方针

参考一个英雄时，优先实现或简化复刻英雄本身的技能、核心循环和辨识度。只有在原英雄的关键机制已经完成映射、差异已经公开记录并经过可运行验证后，才考虑增加新技能。

这里的“复刻”指机制学习和本地原型验证，不要求复制原作的美术、文本、地图节奏或完整数值平衡。目标是保留角色为什么是这个角色，再把它转译成 Gemheart 的 3D 横版动作规则。

## 实现优先级

每个参考英雄按以下顺序处理：

1. **身份机制**：被动、核心输出循环、主要防御方式、招牌控制或终结机制。
2. **可玩骨架**：基础攻击、移动、技能目标类型、资源、冷却和技能之间的状态关系。
3. **横版动作化**：前摇、有效帧、后摇、取消窗口、命中停顿、硬直、霸体、击退、击飞和纵深判定。
4. **表现绑定**：动画、VFX、音效、朝向、层级和生命周期。
5. **原创扩展**：新的技能、额外形态或团队机制。

原创扩展不能用来掩盖尚未处理的参考技能。若提前保留已有原创内容，英雄档案必须标记为 `original_legacy`，并列出尚未完成的身份机制。

## 改编等级

每个技能和被动都必须选择一个等级：

| 等级 | 含义 | 要求 |
| --- | --- | --- |
| `faithful` | 目标、触发、主要效果和公式结构均保留 | 允许只改变数值尺度和动作帧 |
| `simplified` | 保留核心功能，但删除次级规则、层数或分段成长 | 必须列出删除内容和原因 |
| `adapted` | 保留角色意图，但因横版动作玩法改变目标、伤害类型或时序 | 必须说明玩家体验仍如何保持身份 |
| `original` | 原参考英雄没有的新增内容 | 只能在身份映射完成后加入 |
| `original_legacy` | 规则建立前已存在的原创内容 | 可以保留，但不能视为参考技能已经完成 |
| `missing` | 尚未实现 | 必须进入待办或明确决定不实现 |

## 来源规则

外部玩法数据会变化，因此每次英雄工作都必须重新查阅，而不能只凭记忆。英雄档案至少记录：

- 目标游戏和模式，例如 `League of Legends PC`，不能混用 Wild Rift、TFT、Arena 或历史版本。
- 查阅日期、页面网址以及已知补丁或页面修订信息。
- 基础属性、成长值、技能描述、伤害类型、目标类型、持续时间和公式结构。
- 哪些值直接采用、经过单位换算、经过简化或由项目自行设计。
- 无法确认的信息和暂时假设。

来源优先级为：当前官方玩法页面或补丁说明、当前 Wiki 数据模板、Wiki 机制页面、历史资料。若来源冲突，记录冲突并选择目标版本；不得静默混用。

只摘录机制和必要数字，使用自己的语言描述，不复制大段原文或原作资产。

## 公式可追溯性

每个实际参与结算的公式必须归入一种来源类型：

- `reference`：结构或数值直接来自外部参考，必须提供网址和查阅日期。
- `derived`：由参考数据换算到 Godot 世界单位或横版节奏，必须写出换算式。
- `project`：Gemheart 自有规则，例如硬直、霸体、击退衰减或原创技能；提供本地规则 ID 或代码位置，不能伪造 Wiki 来源。

公式必须在 [公式与来源索引](formula-reference.md) 或英雄档案中出现，并最终落实到 `combat_rules`、单位属性、技能效果、Buff、命中配置或类型化公式代码。禁止只在文档里存在，也禁止把可配数值藏在角色脚本中。

## LoL 到横版动作的转译

参考技能进入 Gemheart 时，必须额外回答：

- 技能在 X/Z 平面的命中形状和纵深容差是什么？
- 施法期间能否移动、转向或被打断？
- 前摇、有效期、后摇和取消窗口分别是什么？
- 命中造成多少 hitstop、hitstun、poise damage、knockback 和 launch velocity？
- 多段攻击是按固定时间、动画帧还是事件触发？同一目标的重复命中规则是什么？
- VFX 和音效是跟随动画、Buff 持续时间、固定时长还是手动生命周期？
- 面向左侧时，角色、特效、命中盒、阴影和 UI 锚点是否保持同一逻辑原点？
- 序列帧是否采用作者空间 `(0, 0)` 枢轴（角色脚底、脱手法球/爆炸中心、地面特效接地点）？导入器是否把 JSON `originPixel` 写成节点原点，而不是画布几何中心？出手点和命中点是否只作为实例 Transform，没有画进帧？

LoL 的范围值、移动速度和碰撞半径不能直接当作 Godot 米使用。保留来源值，并通过明确的 `conversion_scale` 得到运行时值。

脱手法球、受击爆炸与角色脚底共用作者 `(0, 0)`，和三维资产一样。导入器必须读 `originPixel`。禁止把画布几何中心当作飞行特效锚点，也禁止把「手在角色身上的像素位置」画进序列帧。地面法阵仍用脚底/地面枢轴。已验收英雄的米制 bias 是导入补丁，不是通用标尺。详细履约见 [瑞兹档案脱手法球约定](heroes/ryze.md)。

## 标准工作流

1. 创建或更新 `docs/combat/heroes/<hero_id>.md` 来源快照。
2. 写一句角色身份描述，并列出不能丢失的机制。
3. 为被动和每个参考技能建立映射矩阵，标记改编等级。
4. 列出所有计算公式、来源网址、单位和简化决策。
5. 将身份、属性、技能、效果、Buff、命中帧和表现分别写入对应源表。
6. 构建数据库，修复全部引用、枚举、资产和生命周期错误。
7. 添加数值测试、机制测试和完整场景回归。
8. 在交付说明中报告忠实项、简化项、原创项、未实现项和验证结果。

## 原创技能准入条件

增加新技能前至少满足：

- 参考英雄的被动与所有基础技能都有明确映射状态。
- `missing` 项不会破坏角色核心身份，或者已有书面延期理由。
- 新技能说明其解决的横版玩法问题，而不只是“需要更多技能”。
- 新技能拥有独立的公式来源类型、帧数据、打击规则和测试。
- 新技能不会覆盖、重复或无条件强化原有技能的职责。

## 完成定义

英雄实现只有在以下项目可验证时才算完成：

- 来源快照和改编矩阵完整。
- 所有运行时数字可追溯到 CSV 或 `combat_rules`。
- 参考公式、换算公式和项目公式均已登记。
- 角色左右朝向、纵深、移动施法和生命周期通过场景测试。
- 数据库构建、英雄机制测试和完整战斗回归全部通过。
